Earlier in this line of previews

The pitch and import work below shipped in an earlier preview and is still current.

This preview replaces the pitch path with a machine-learned estimator and removes two hard-coded limits. Everything described here runs on the device.

SPICE pitch estimation

Pitch is estimated by SPICE, a self-supervised pitch model from Google Research, running on TensorFlow Lite on the device. It replaces the uncalibrated autocorrelation estimate the earlier previews used.

Practice in the song's key

The MIDI key signature is now read, so pitch practice targets the song's own tonic instead of a fixed A. A song in A minor targets 440 Hz; one in C major targets middle C.

An honest pitch meter

The meter no longer displays a perfect score before any audio arrives. It stays neutral until the microphone reports a reading, and a new game clears the previous result.

Import without a ceiling

SoundFont import no longer rejects banks over 32 MB. The file is mapped for validation and streamed into the loader, and a malformed bank is still refused.

In detail

  • The model. assets/spice.tflite, 8,733,770 bytes, SHA-256 b88f96ffa5d0691a50774f7843ba2356bbddd5fb33981ef1913c9b06afe25e07. Apache-2.0, with its licence text bundled offline in the app's runtime notices alongside the TensorFlow Lite runtime's own.
  • The runtime. org.tensorflow:tensorflow-lite:2.16.1. It declares no permissions and pulls in no Google Play services, so the app's permission set is unchanged: camera, microphone and internet only.
  • Nothing is uploaded. The model runs locally. No microphone audio leaves the device, and no audio is saved.
  • One microphone owner. The estimator is handed the same captured audio the monitor already receives. It never opens a second capture, so nothing contends with the existing microphone, scoring or monitoring paths.
  • An optional path, not a dependency. Audio is captured at 48 kHz and the model consumes 16 kHz, so the app resamples with a filter that rejects 20 kHz content by 65 dB before it can fold back into the model's band. The model's published output is not a frequency; the app applies its documented calibration. If the model cannot be loaded, the app falls back to the previous frame detector rather than failing.
  • The key signature. Android previously skipped MIDI meta event 0x59 entirely. It is now parsed, and the tonic pitch class it implies is converted into a practice note in the octave of middle C, so all thirty real key signatures land between 261.6 Hz and 493.9 Hz. A file with no key event falls back to A4, and the voice coach now receives the song's real key instead of always reporting C major.
  • Validation before the loader. The SoundFont validator that inspects a bank's cross-table references before it reaches the third-party loader is unchanged and still runs first; it now maps the file instead of copying it into memory, which is what removed the 32 MB ceiling.
  • Import progress. A progress dialog reports copying, validation and completion for songs, folders and SoundFonts, and reports once per import rather than once per file.
  • Size. The APK grows from 25.8 MB to 44.2 MB. The model is 8.3 MB, and the runtime adds about 9.7 MB across the three packaged ABIs. That was accepted deliberately rather than falling back to a smaller, less accurate model.

Automatic checks passed on this source: the Android build, lint, the native SoundFont sanitizer, the host-JVM domain regressions and the emulator runtime checks. Pitch accuracy, latency, the confidence threshold and large-bank SoundFont behaviour have not been verified on a physical device.

Newer than this page

These are the parts of the current preview that are easiest to miss, because most of them only appear once the app is open. Everything described here runs on the device.

A stage that asks for a song

An idle stage no longer shows a still image. It shows a KARAOKE READY badge, the song-code prompt 00000 in monospace cyan, and the line “Enter a song code to sing” over the bundled background video. The prompt appears only while nothing is playing and clears as soon as a song loads.

Background video that shuffles

Five bundled background clips ship with the app and rotate on a timer, so a long night does not sit on one loop. Auto-shuffle and its interval are settings, and your own photo or video choice still takes priority.

A control deck behind the word mark

Tapping the KANTA word mark opens a hardware-style control screen: a master volume dial in the centre with search, queue, visuals, controls, pitch, coach, playback, microphone, monitor, camera, fullscreen, key and tempo around it. Back returns to the screen you left, so the deck is never a place you can get stuck.

Versions that advance

The version name is derived from the same build number as the version code instead of a frozen literal, so two published previews can no longer share one label. This page states the exact source and APK digest for the build it offers.

Also in the current build

  • Pair by scanning the stage. Kanta-Connect can display its pairing QR code directly on the karaoke stage. The network address and the pairing code stay separately copyable and are never combined into one string, which keeps a single-session code from leaking through the clipboard.
  • A General MIDI bank without the hunt. With no SoundFont selected, the app downloads FluidR3 GM (~148 MB) itself with live progress, and skips the download when the bank is already present.
  • One brand, in one place. The word mark and its tagline live in the header only; the duplicated in-page banner is gone.
  • Search that waits for the whole code. Typing in the Home search no longer navigates on the first digit. The entry is committed when you submit it, which is what a song-code field should do.

The standby stage and the control deck are asserted by the emulator runtime checks, including that the standby background is moving video rather than a still frame. Neither has been seen on physical hardware.

Camera, voice and remaining work

The downloadable build includes personal photo/video backgrounds, optional front-camera preview and opt-in microphone input level/pitch estimates. Camera is off by default, requests permission only when enabled, records nothing and turns off when you leave KANTA. Experimental wired/USB monitoring with Dry, Room, Hall and Echo is available in voice settings. It needs a separate opt-in, starts quietly and disables itself on a detected output change. Physical output, feedback and delay remain unverified; older Android reports only one route. Optional song scoring gives an informal pitch-following estimate for a single identified MIDI melody. Turn on scoring and microphone input separately in Control; silence or unreliable input produces no score. MP3/WAV and ambiguous melody references are not scored. Timing needs device calibration, and backing music can affect it. Optional experimental pitch correction is now available after wired/USB monitoring is verified. Turn it on separately in voice settings; it starts off each time monitoring begins. It follows nearby musical notes rather than the song melody, adds delay and may change voice tone or create artifacts. Dry scoring stays unchanged. Experimental Android-to-Android companion control is included. In Control, open Companion control on both devices. On the host, select its private network address and choose Start hosting. On the other Android device, enter that address and the full private 32-character code, then Connect. Share the code only with someone you trust: it grants song search, reservations, cancellation and Play/Pause/Next. The code expires in five minutes, and a session lasts up to ten minutes. Stop or leaving either app disconnects it; returning does not reconnect. Song and singer details are encrypted in transit; music and recordings are not sent. iPhone/iPad pairing is not compatible. Physical two-device testing and independent security review remain open. YouTube remains unavailable. Voice search uses your device's selected recognition provider and may need an internet connection.

Testing preview

These are recovered development builds, not store releases. Android emulator checks and iPhone/iPad simulator walkthroughs passed. Before changing test builds

Separate CI builds can use different debug signing certificates. Android may require uninstalling the older preview first, which removes app-private state. Keep your original music and explicit exports backed up. These bundles are for testing, outside Google Play.
