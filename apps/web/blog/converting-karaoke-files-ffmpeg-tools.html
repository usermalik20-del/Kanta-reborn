Converting Karaoke Files: FFmpeg, Tools, and Batch Processing

October 13, 2026By KANTA Team16 min read

You've collected hundreds of karaoke tracks over the years. They're in different formats — MIDI, KAR, MP3+CDG, WAV, maybe even some obscure proprietary formats. Now you want them all in one place, playable on any device, with consistent metadata and synchronized lyrics. This guide walks you through the tools, commands, and workflows to make it happen.

Why Convert at All?

Format fragmentation is the silent killer of karaoke libraries. A typical collection accumulated over a decade contains:

  • MIDI/KAR files from early 2000s karaoke software
  • MP3+CDG pairs from CD ripping
  • WAV files from professional backing track purchases
  • Proprietary formats from discontinued apps (KFN, KOK, VS)

Each format has different capabilities. MIDI/KAR supports tempo/pitch changes and instrument muting. Audio formats don't. CDG has pixel-perfect lyrics timing but huge file sizes. Converting to a unified format — or at least a managed set of formats — gives you:

  • Consistent playback across devices
  • Metadata search by artist, title, genre, key, tempo
  • Batch operations — normalize volume, strip silence, embed artwork
  • Future-proofing — avoid format obsolescence

FFmpeg: The Swiss Army Knife

FFmpeg handles virtually every karaoke-relevant format. Install it once, use it forever.

# macOS
brew install ffmpeg

# Linux (Debian/Ubuntu)
sudo apt install ffmpeg

# Windows
winget install ffmpeg
# or download from ffmpeg.org

Key flags you'll use constantly:

FlagPurpose
-iInput file
-c:aAudio codec (libmp3lame, pcm_s16le, aac, flac)
-b:aAudio bitrate (192k, 320k, etc.)
-arSample rate (44100, 48000)
-acChannels (1=mono, 2=stereo)
-afAudio filters (volume, normalization, silence removal)
-map_metadataCopy metadata between files
-id3v2_version 3Write ID3v2.3 tags (widest compatibility)

Common Karaoke Conversions

MP3+CDG → MP3 (audio only)

Extract audio from CDG pairs. CDG is a separate graphics file — FFmpeg can't read it directly, but you can extract the MP3 audio:

ffmpeg -i song.mp3 -c:a libmp3lame -b:a 320k -id3v2_version 3 song_audio.mp3

Note: You lose the CDG lyrics. For full CDG→video conversion, see the cdg2mp4 tool below.

WAV → MP3 (high quality)

ffmpeg -i backing.wav -c:a libmp3lame -b:a 320k -id3v2_version 3 backing.mp3

For archival, use FLAC instead:

ffmpeg -i backing.wav -c:a flac -compression_level 5 backing.flac

MIDI → Audio (requires SoundFont)

FFmpeg can render MIDI to audio if you have a SoundFont:

ffmpeg -i song.mid -c:a libmp3lame -b:a 320k \
  -f lavfi -i "amovie=FluidR3_GM.sf2:loop=0" \
  -filter_complex "[0:a][1:a]amix=inputs=1" \
  song_rendered.mp3

Better: use fluidsynth directly for MIDI rendering (see below).

Video → Audio (extract backing track)

ffmpeg -i karaoke_video.mp4 -vn -c:a libmp3lame -b:a 320k backing.mp3

-vn drops video stream. Use -c:a copy to extract without re-encoding if the audio is already MP3/AAC.

Metadata: The Invisible Backbone

Metadata lets you search, sort, and filter. Karaoke needs more than standard ID3 tags.

Writing Tags with FFmpeg

ffmpeg -i input.mp3 -c:a copy \
  -metadata title="Don't Stop Believin'" \
  -metadata artist="Journey" \
  -metadata album="Escape" \
  -metadata genre="Rock" \
  -metadata date="1981" \
  -metadata comment="KANTA_CODE=JOU-001-DSB" \
  -id3v2_version 3 \
  output.mp3

Batch Tagging from CSV

If you have a spreadsheet with metadata, use a script:

#!/bin/bash
# tag_from_csv.sh
# CSV format: filename,title,artist,album,genre,year,bpm,key,code

while IFS=',' read -r file title artist album genre year bpm key code; do
  [[ "$file" == "filename" ]] && continue  # skip header
  ffmpeg -i "$file" -c:a copy \
    -metadata title="$title" \
    -metadata artist="$artist" \
    -metadata album="$album" \
    -metadata genre="$genre" \
    -metadata date="$year" \
    -metadata comment="KANTA_CODE=$code" \
    -id3v2_version 3 \
    "tagged/$file"
done < metadata.csv

Audio Normalization: Consistent Volume

Nothing ruins a karaoke session like blasting from one track to a whisper on the next. EBU R128 loudness normalization is the broadcast standard.

Single File (FFmpeg)

# Analyze loudness
ffmpeg -i song.mp3 -af loudnorm=I=-16:TP=-1.5:LRA=11:print_format=json -f null -

# Normalize to -16 LUFS (standard for streaming)
ffmpeg -i song.mp3 -af loudnorm=I=-16:TP=-1.5:LRA=11 -c:a libmp3lame -b:a 320k song_norm.mp3

Batch Normalization (Python + FFmpeg)

#!/usr/bin/env python3
# normalize_batch.py
import subprocess, json, os, sys

TARGET_LUFS = -16.0
TARGET_TP = -1.5
TARGET_LRA = 11.0

def analyze_loudness(filepath):
    cmd = [
        'ffmpeg', '-i', filepath,
        '-af', f'loudnorm=I={TARGET_LUFS}:TP={TARGET_TP}:LRA={TARGET_LRA}:print_format=json',
        '-f', 'null', '-'
    ]
    result = subprocess.run(cmd, capture_output=True, text=True)
    # FFmpeg outputs JSON to stderr for loudnorm
    for line in result.stderr.split('\n'):
        if line.startswith('{'):
            return json.loads(line)
    return None

def normalize_file(input_path, output_path, measured):
    cmd = [
        'ffmpeg', '-y', '-i', input_path,
        '-af', f'loudnorm=I={TARGET_LUFS}:TP={TARGET_TP}:LRA={TARGET_LRA}:'
               f'measured_I={measured["input_i"]}:'
               f'measured_TP={measured["input_tp"]}:'
               f'measured_LRA={measured["input_lra"]}:'
               f'measured_thresh={measured["input_thresh"]}:'
               f'offset={measured["target_offset"]}:'
               f'linear=true:print_format=summary',
        '-c:a', 'libmp3lame', '-b:a', '320k',
        '-id3v2_version', '3',
        output_path
    ]
    subprocess.run(cmd, check=True)

if __name__ == '__main__':
    input_dir = sys.argv[1]
    output_dir = sys.argv[2]
    os.makedirs(output_dir, exist_ok=True)
    
    for fname in sorted(os.listdir(input_dir)):
        if not fname.lower().endswith(('.mp3', '.wav', '.flac', '.m4a')):
            continue
        in_path = os.path.join(input_dir, fname)
        out_path = os.path.join(output_dir, fname)
        print(f"Analyzing {fname}...")
        measured = analyze_loudness(in_path)
        if measured:
            print(f"  Input: {measured['input_i']:.1f} LUFS → Target: {TARGET_LUFS} LUFS")
            normalize_file(in_path, out_path, measured)
            print(f"  ✓ Done")
        else:
            print(f"  ✗ Failed to analyze")

Trimming Silence: Clean Intros/Outros

Many karaoke tracks have 5-10 seconds of silence at start/end. Auto-trim:

# Remove silence longer than 0.5s below -40dB
ffmpeg -i input.mp3 -af "silenceremove=start_periods=1:start_threshold=-40dB:start_duration=0.5,dareverse,silenceremove=start_periods=1:start_threshold=-40dB:start_duration=0.5,dareverse" -c:a libmp3lame -b:a 320k trimmed.mp3

For batch processing, the Python script above can incorporate this filter.

Specialized Karaoke Tools

FFmpeg is general-purpose. These tools are built for karaoke:

cdg2mp4 / cdg2video

Convert MP3+CDG pairs to MP4 video with burned-in lyrics:

# Install (Python)
pip install cdg2mp4

# Convert
cdg2mp4 song.mp3 song.cdg -o song.mp4

# Batch
for f in *.mp3; do
  base="${f%.mp3}"
  [[ -f "$base.cdg" ]] && cdg2mp4 "$f" "$base.cdg" -o "$base.mp4"
done

Karaoke Mugen Tools

The Karaoke Mugen project has excellent open-source tools:

  • kmtool — metadata extraction, validation, conversion
  • karaokebase — database management

Midicsv / Csvmidi

Convert MIDI ↔ CSV for programmatic editing:

# MIDI → CSV (edit in Excel/Python)
midicsv song.mid song.csv

# CSV → MIDI
csvmidi song.csv song.mid

This lets you bulk-edit tempo, key, instrument assignments, or insert lyric events programmatically.

FluidSynth (MIDI → Audio)

Better than FFmpeg for MIDI rendering:

# Install
brew install fluidsynth  # macOS
sudo apt install fluidsynth  # Linux

# Render with specific SoundFont
fluidsynth -ni FluidR3_GM.sf2 song.mid -F song_rendered.wav -r 44100

# Batch render
for f in *.mid; do
  fluidsynth -ni FluidR3_GM.sf2 "$f" -F "${f%.mid}.wav" -r 44100
done

Complete Batch Processing Workflow

Here's a production-ready pipeline for a folder of mixed karaoke files:

#!/bin/bash
# karaoke_batch_process.sh
# Usage: ./karaoke_batch_process.sh /input/folder /output/folder

set -euo pipefail

INPUT="$1"
OUTPUT="$2"
SOUNDFONT="/usr/share/sounds/sf2/FluidR3_GM.sf2"  # adjust path

mkdir -p "$OUTPUT"/{audio,video,logs}

log() { echo "[$(date '+%H:%M:%S')] $*" | tee -a "$OUTPUT/logs/process.log"; }

log "Starting batch process on $INPUT"

# 1. Inventory
find "$INPUT" -type f \( -iname '*.mid' -o -iname '*.kar' -o -iname '*.mp3' -o -iname '*.wav' -o -iname '*.flac' -o -iname '*.m4a' -o -iname '*.cdg' \) | sort > "$OUTPUT/logs/inventory.txt"
TOTAL=$(wc -l < "$OUTPUT/logs/inventory.txt")
log "Found $TOTAL files"

# 2. Process each file
CURRENT=0
while IFS= read -r file; do
  CURRENT=$((CURRENT + 1))
  rel="${file#$INPUT/}"
  base="${rel%.*}"
  ext="${file##*.}"
  out_base="$OUTPUT/audio/$base"
  
  log "[$CURRENT/$TOTAL] Processing: $rel"
  
  case "${ext,,}" in
    mid|kar)
      # MIDI/KAR → MP3 via FluidSynth
      if [[ -f "$SOUNDFONT" ]]; then
        fluidsynth -ni "$SOUNDFONT" "$file" -F "$out_base.wav" -r 44100 2>>"$OUTPUT/logs/errors.log"
        ffmpeg -y -i "$out_base.wav" -af loudnorm=I=-16:TP=-1.5:LRA=11 -c:a libmp3lame -b:a 320k -id3v2_version 3 "$out_base.mp3" 2>>"$OUTPUT/logs/errors.log"
        rm -f "$out_base.wav"
        log "  ✓ Rendered MIDI → MP3"
      else
        log "  ⚠ SoundFont not found, skipping MIDI render"
      fi
      ;;
    mp3|wav|flac|m4a)
      # Audio: normalize + copy tags
      ffmpeg -y -i "$file" -af loudnorm=I=-16:TP=-1.5:LRA=11 -c:a libmp3lame -b:a 320k -id3v2_version 3 -map_metadata 0 "$out_base.mp3" 2>>"$OUTPUT/logs/errors.log"
      log "  ✓ Normalized audio"
      ;;
    cdg)
      # CDG: check for matching MP3
      mp3_file="${file%.cdg}.mp3"
      if [[ -f "$mp3_file" ]]; then
        cdg2mp4 "$mp3_file" "$file" -o "$OUTPUT/video/$base.mp4" 2>>"$OUTPUT/logs/errors.log"
        log "  ✓ CDG+MP3 → MP4"
      else
        log "  ⚠ No matching MP3 for CDG"
      fi
      ;;
  esac
done < "$OUTPUT/logs/inventory.txt"

log "Batch complete. Output in $OUTPUT/audio/ and $OUTPUT/video/"
log "Errors (if any) in $OUTPUT/logs/errors.log"

Importing into KANTA

After conversion, import your library into KANTA:

  1. Open KANTA → My Songbook → Import
  2. Select your processed folder
  3. KANTA reads embedded metadata (title, artist, BPM, key, custom KANTA_CODE)
  4. Review and confirm matches
  5. Your library is now searchable, filterable, and ready for offline use

KANTA's .kanta-book export format preserves all metadata for backup or sharing (see Private Songbook Export).
